# 擦除架构 v6：参考帧优先 + 白字门控

最后更新：2026-11-02  
代码：`scripts/erase_ref.py`（引擎）、`scripts/pipeline.py`（生产入口）、`webapp/convert.py`（网页入口）  
基准记录：`bench/video_inpaint/HYBRID_ROUTING.md`

## 1. 为什么换

旧链路按 cue 时间窗给每帧生成 d20 笔画掩码，再逐帧跑 LaMa。实测有三个根因：

1. **cue 时间和烧录字幕对不上**：1168 帧里有 136 帧被无谓擦除，复杂背景（编织绳、毛领、幕布）上出现平块和抖动。
2. **笔画掩码漏短笔画**：白字里的点、撇、抗锯齿边没有完全盖住，模型输出残留白点。
3. **逐帧模型重绘**：即使掩码正确，LaMa 每帧补出的纹理都在变，落在静止背景上像“呼吸”。

v6 的结论：**能用真实像素就别用模型**。只有找不到干净参考、或参考帧配准失败时才让模型补。

## 2. 路由

```text
镜头字幕轨 ──> 逐帧白字检测（不是 cue 时间）
                  │
        ┌─────────┴─────────┐
     有字帧                 无字帧
        │                    │
   连续段分组              原样保留（不擦）
        │
   段中心最近的干净帧
        │
   DIS 光流 + 字幕区光流 TELEA 修补
        │
   光度校验（mask 外环）──通过──> 参考帧真实像素回填（feather 1.0）
        │
        └──失败/无参考──> LaMa 模型兜底（feather 2.5）
                              │
                        仅兜底帧做时域稳定
```

## 3. 掩码契约

### 3.1 搜索区

镜头内所有字幕轨的 `ubox` 并集 + 约 0.1 字高 padding。只在搜索区内找白字，避免把人物衣服、反光当成字幕。

### 3.2 白字门控

对字幕带逐帧：

```text
min(B,G,R) > 185，R-B < 22
连通域面积 >= 0.003 * fh²
0.10 * fh <= 高 <= 1.20 * fh，宽 <= 3.50 * fh
组件总像素 >= 0.016 * fh²  →  该帧“有字”
```

`fh` 取字幕轨 `ubox` 的中位高度（没有 ubox 时取 OCR 框高度 × 1.15）。命中后：

- 保留所有合格组件；
- **把检测到的整行 bbox 内所有白色像素都并入掩码**——短笔画、抗锯齿、字形断开的部分不会漏；
- 按 `mask.dilate`（默认 20）膨胀，覆盖黑描边和光晕。

门控结果为空、或“有字帧 < 45% 轨活跃帧”时，整镜头自动回退旧 `erase_shot_legacy`（低对比/彩色字幕等异常素材仍然能擦，不会静默不处理）。

### 3.3 两套掩码

| 用途 | 掩码 |
|---|---|
| 参考帧回填 | 白字掩码 + 掩码外 25px 环内的亮白抗锯齿像素 |
| 模型兜底 | 生产 d20 笔画/矩形掩码 ∪ 白字掩码（保证白字全覆盖） |

## 4. 参考帧填充

1. 每段连续有字帧取段中心最近的**无字帧**作参考；整段固定一张，避免多参考中值把不同时刻的纹理揉糊。
2. 半分辨率 DIS 光流（`MEDIUM`）把参考帧对齐到当前帧。
3. **光流场在字幕掩码内先做 TELEA 修补**再 warp；否则白字笔画会把流场带偏，背景出现拖影。
4. 用 `mask` 外 21px 环做光度校验，平均绝对误差 ≤ `erase.ref_photo`（默认 12）才接受。
5. 通过后按环上均值做逐通道色偏补偿，再用 feather 1.0 把真实参考像素贴进掩码。
6. 失败或无干净参考 → 模型兜底，并用 feather 2.5 过渡。

处理带会在字幕框外扩 35% 宽、25% 高（至少 96/32px），给光流和光度校验足够背景。v6 基准直接用了整幅宽度，生产版保留同样的思路。

## 5. 模型兜底与时域稳定

- 兜底模型沿用生产配置：`inpaint.backend` 的 LaMa（native fp16 或 TorchScript），画布和批大小与旧链路一致。
- **只对模型帧做时域稳定**（`erase.model_stab`，默认 0.45）；参考帧是真实像素，不参与平滑。
- 模型帧之间仍用运动补偿（DIS）混合，切镜/遮挡自动放弃混合，避免拖影。

## 6. 生产集成点

| 位置 | 作用 |
|---|---|
| `scripts/pipeline.py:erase_shot` | 统一入口；`erase.engine: ref` 走新引擎，`legacy` 走旧逻辑 |
| `scripts/erase_ref.py:erase_shot_ref` | v6 引擎本体 |
| `webapp/convert.py:erase` | 网页任务调用同一个 `P.erase_shot`，自动获得新引擎 |
| `scripts/pipeline.py:auto_repair` | 擦除后 OCR 复查 + 只返修命中镜头的兜底网 |
| `config.yaml:erase.engine` | `ref` / `legacy` 切换 |
| `config.yaml:mask.white_level/white_sat` | 白字门控阈值 |

可调参数：

```yaml
erase:
  engine: ref
  ref_photo: 12.0
  ref_feather: 1.0
  model_feather: 2.5
  model_stab: 0.45
mask:
  dilate: 20
  white_level: 185
  white_sat: 22
```

## 7. 基准结果（39s demo，1080×1920，30fps）

v6 离线基准（1168 帧）：

- 796 帧有字：739 帧参考填充（93%），57 帧模型兜底（5%），372 帧原样保留（32%）；
- 白字残留审计 0，OCR 8 次抽检 0 可疑；
- 干净参考越近，纹理越接近原片；参考跨度大的镜头（幕布 #06、木纹 #11）仍是模型兜底。

生产移植在镜头 0/5/13 上复跑，路由与 v6 一致（52/52、65/1、47/0 参考帧），输出与 v6 成片带区差异约 2.0（H.264 重编码量级）。

2026-11-02 生产端到端（webapp `convert`，同一 39s demo，中文→日语）：

- 18 条日语，翻译 18/18；字号 72px、每行 12 字，按原字幕位置压制；
- 白字残留审计 796 个有字帧全部为 0；`auto_repair` 0 处；QC 0 可疑；
- 端到端 208.7s（V100，擦除约占 150s，约 9 fps）；音频保留，1080×1920；
- 镜头 3/5/6/7/11/13/14 的掩码区 d2 与 v6 持平或略低，Laplacian 细节略高
  （例：镜头 6 d2 1.32 vs 1.40、lap 22.9 vs 21.0；镜头 14 d2 16.68 vs 17.69）。

## 8. 已知边界

- **整镜头没有无字帧**：整段都会走模型兜底，复杂纹理仍可能轻微软化。
- **参考帧太远且背景运动大**：光度校验会拒绝，交给模型；不会硬贴。
- **非白/低对比/彩色字幕**：白字门控可能失败，自动回退 legacy；这类素材建议用云端精细化。
- **参考帧里若有其他画面文字**：搜索区只覆盖本镜头字幕轨，正常不会带进来；但极端同位置水印需要人工确认。
- 生产兜底是 LaMa；bench 里的 ProPainter 只用于离线对比，不在默认链路。

## 10. 日语字幕

- CLI：`--target ja`；网页：目标语言选「日本語」。
- 翻译：Hy-MT2 逐句直译，中文提示词 `将以下文本翻译成自然、口语化的日语…`；校验要求译文含假名，防止中文原文直接漏过。
- 排版：`cues.wrap_lines` 对 CJK 按字折行，带避头尾（`。、，！？` 不落行首，`（「『` 不落行尾）和**两行平衡断点**（优先脚本边界/助词，避免“組み合わ/せ”）。
- 网页：日文字号 = 原字幕字高（1.0×），每行 12 字、最多 2 行；位置沿用原字幕边距。CLI：底部、每行 18 字。
- 字体：`Noto Sans CJK JP`（`webapp/convert.py:LANG_FONT`）。
