# 运动帧的马赛克/抖动：先用邻帧真实像素补洞（2026-11-04）

问题：字幕区在**背景运动**的帧上看起来像一块会抖的模糊块——模型每帧都凭空重画一遍，
纹理和亮度在帧间跳，边缘也跟着闪。

思路：字幕确实固定在一个区域，但**同一个像素不是每一帧都被字盖住**。字幕在动、字也在变，
像素 (x,y) 在第 k 帧被字盖住，常常在第 k±1..k±3 帧里是露出来的。把这些真实像素按光流
warp 回第 k 帧填进字幕区，剩下的洞（几帧里都被字盖住）才交给 LaMa。
填进去的是真纹理，而且随背景一起动——既不发糊也不会抖。

## 1. 实现（`scripts/erase_ref.py:_temporal_fill`）

```
对每个「参考帧填不了、要进模型」的帧 k：
  for d in 1..tf_radius:  for j in (k-d, k+d):
      1) 邻居 j 的灰度图里，把 j 自己的字幕区用大核中值模糊盖掉（避免光流被静止白字带偏）
      2) DIS(ULTRAFAST) 半分辨率算 j→k 光流，把 j 的**原始 band** warp 到 k
      3) 对齐质量闸：掩码外的像素有 ≥55% 对得上（<tf_thr）才认这个邻居
      4) 有效像素 = warp 后落在邻居「无字”区域（白字掩码膨胀 9px）+ 落在当前帧掩码内
  逐像素按「时间上由近到远」挑第一个有效真实像素填进去
  剩下的洞 × 再查一遍白字（填完还发白的退回）→ 交给 LaMa
```

- 只在掩码外接框（外扩 16px）里算，不做整带运算。
- 邻居灰度图按帧号缓存，同一邻居在多帧里复用时不再重算。
- 光流对象按线程各建一个：`cv2.DISOpticalFlow` 不是线程安全的，pipe=2 共用会直接段错误。

## 2. 效果（ep04，89.8s / 2245 帧 / 49 镜头，pipe=2）

| | 现状（纯 LaMa） | 邻帧补洞 |
|---|---:|---:|
| 擦除墙钟 | 158.6s | **206.4s** |
| 成片帧数 | 2245 | 2245（精确） |
| GPU 均值 | 45% | 14.8%（变成 CPU 密集） |
| 残留复查 | 5 处（老位置） | 5 处（同位置） |

代价 +30% 擦除时间，换来字幕区是真实纹理。视觉对比（同样两段镜头）：

- t=39.6s 铁网后的楼梯：LaMa 把铁网糊成一团雾，邻帧补洞把铁条/扶手补回来。
- 校服白布料 + 红印花：LaMa 抹成灰平片，邻帧补洞保住印花走向和褶皱。

## 3. 第一版踩的坑

1. **取中值用错了哨兵值**：无效候选填 0 参与排序，`cnt//2` 会挑到 0，掩码区直接变黑块。
   改成「按时间从近到远挑第一个有效像素」，顺带把单帧 20ms 的全排序省掉。
2. **邻帧白字没检全**（弱字/描边）→ 补进去的还是带字像素，残留复查多出 2 处。
   现在填完再查一遍白字门限，还发白的退回给 LaMa。
3. **DIS 实例共用导致段错误**：pipe=2 整片跑到一半 core dump。

## 4. 和「先裁剪再处理」的关系

模型（LaMa 1024×256 画布）、光流、时域补洞、OCR 本来就全在字幕带上跑，只有**解码**和
**编码**是整帧的（成片是全片）。按「只喂字幕带、让 ffmpeg 把带贴回源片再编码」实现了
`open_overlay_writer`（`ERASE_WRITE=overlay`）：

- 逐位一致（和整帧路径比 PSNR = inf），说明叠回去没有错位。
- 时间只快 2%（25.8s → 25.2s / 6 镜头），因为解码编码都在 ffmpeg 子进程里、和 CPU 侧重叠，
  本来就不是瓶颈。
- 但内存带宽从 6.2MB/帧降到 ~1MB/帧，批量跑时 K 能开更高。默认仍走整帧路径，
  `ERASE_WRITE=overlay` 可开。

## 5. 参数

```yaml
erase:
  tf_radius: 2        # 用前后各几帧的真实像素补（0=关，退回纯 LaMa + 时域混合）
  tf_thr: 18.0        # 邻居 warp 对齐质量阈值（掩码外平均差）
  stab_thr: 24.0      # 时域混合的逐像素可信度阈值（0=老行为：整帧统一 alpha）
```

回滚：`tf_radius: 0`（或 `VE_TF_RADIUS=0`）——行为与之前逐位一致，除了时域混合那点差异。
