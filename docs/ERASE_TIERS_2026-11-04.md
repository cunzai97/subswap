# 三级分流：参考帧 → LaMa → ProPainter（2026-11-04）

之前只做了两级：参考帧填充（一档）+ LaMa 兜底（二档）。这一步把 bench 里验证过、
但没接进生产的第三档补上：**参考帧填不了的帧，按难度决定交给 LaMa 还是 ProPainter**。

## 1. 为什么要分档

三档各自擅长的事不一样：

| 档 | 手段 | 强项 | 弱项 |
|---|---|---|---|
| 一档 | 参考帧 + DIS 光流 warp | 真实像素、零模型幻觉 | 要有干净参考帧、背景得近乎静止 |
| 二档 | LaMa（逐帧图像级） | 快（~18 fps 级）、平滑背景很干净 | **不知道该长什么**：结构化纹理（铁网、栏杆、编织）会被糊成一片 |
| 三档 | ProPainter（时序 + 光流传播） | 能顺着前后帧把结构补出来 | 慢（实测 4.0 fps）、显存大、偶尔有块状伪影 |

关键点：**ProPainter 只处理"确实要模型来编"的帧**，一档能填的帧一个都不给它。

## 2. 落地方式（`scripts/erase_ref.py`）

```
镜头开跑
 ├─ 第 1 遍解码（本来就有）：算白字字形掩码 → 顺序落到 tmp/frames.raw + masks.raw
 │    └─ 同时逐帧记纹理（Laplacian 方差）、运动（与上一帧灰度差），只在字幕带内统计
 ├─ 分档判定（按镜头，不按帧——逐帧换模型会让纹理在帧间跳变，比字幕更显眼）
 │    ├─ 本段一个干净参考帧都没有 → 必进模型
 │    ├─ 镜头纹理中位数 ≥ pp_tex（默认 0 = 关）
 │    └─ 镜头运动中位数 ≥ pp_motion（默认 0 = 关）
 ├─ 选中 → 三档：把「必进模型的帧」挑出来送给 ProPainter（前后各留 2 帧上下文）
 │    └─ 掩码 = max(白字笔画膨胀, 生产笔画掩码)，与 bench v6 兜底口径一致
 └─ 第 2 遍解码：逐帧
      ├─ 参考帧 fill 成功 → 用真实像素（一档赢，PP 结果不用）
      └─ 否则：LaMa 先算（二档基线），再和 PP 结果比掩码内差异
            差异小 → 换成 PP（pp_st["ok"]）；差异大 → 判 PP 幻觉，留 LaMa（pp_st["rej"]）
```

- PP 走 `scripts/pp_engine.py`：**进程内** import ProPainter 的模块（生产解释器本来就能
  import），权重只加载一次常驻，按 chunk（默认 80 帧）跑，跑完只把掩码内像素贴回。
- PP 只吃字幕带自己的裁片（字高 ×0.8 上下留白），不是参考帧填充用的那一大块
  （1080×360 → 600~950×200~330），显存和耗时都省一半。
- 显存账本（V100 16G，实测）：1080×360 40 帧峰值 6.3GB；1080×520 峰值 9.3GB；
  生产裁片跑起来整机峰值 8.2GB（含 LaMa 常驻）。

## 3. ep04 实测（89.8s / 2245 帧 / 49 镜头）

| | 两级（现状） | 三级 |
|---|---:|---:|
| 擦除墙钟（pipe=2） | 158.6s | **280.5s** |
| PP 帧数 | — | 934 帧（42%） |
| PP 计算耗时 | — | 233.6s（4.0 fps） |
| GPU 均值 / p50 | 45% / 25% | **62% / 86%** |
| 显存峰值 | — | 8192MB |
| PP 采纳 / 回退 | — | 858 / 0 |

代价是 **擦除段 1.77×**（PP 每秒 4 帧，是 LaMa 的四五分之一）。收益见下。

## 4. 质量对比

`results` 图：`/home/pan/work/review-scratch/video-erase/probe/pp_zoom_2x.jpg`

- **t=39.6s 铁网后的楼梯**：LaMa 把铁网糊成一团雾、栏杆整段消失；PP 把竖向铁条和
  横向扶手都补回来，网眼还在。这是三档最典型的收益场景。
- **t=41.5s 校服白布料 + 红印花**：LaMa 把布料抹成灰平片、红字断成碎块；PP 保住褶皱，
  红印花的走向能接上。两档在徽章处都留了一点淡影。
- 全片指标：LaMa 版与 PP 版在字幕带上的平均差 1.31、最大 7.3，差异集中在 25% 的帧
  （就是 PP 采纳的那些）。

## 5. 安全闸（目前还没标定，是已知短板）

bench 的口径是「PP 与 LaMa 掩码内平均差 > 20 或 p90 > 85 → 判 PP 幻觉回退」。
这条片子上 **858 帧全部通过、0 回退**——说明阈值相对现在这套裁片/掩码偏宽，
等于没在拦。下一步要么收紧阈值，要么换判据（PP 结果的网格块效应检测、
掩码边界接缝梯度），并在 2–3 条不同题材片上抽查误杀/漏杀。

## 6. 怎么开

```yaml
erase:
  tiers: true          # 默认 false
```

或单次跑用环境变量：`ERASE_TIERS=1`。回滚：`ERASE_TIERS=0` 或 `tiers: false`，
代码路径与两级完全一致（PP 不加载、不占显存）。

阈值也可以临时用 `VE_PP_TEX` / `VE_PP_MOTION` 覆盖做 A/B。

## 7. 还没做的

1. **安全闸标定**（上面第 5 节），现在等于没闸。
2. **批量调度**：PP 峰值 8.2GB，K=4 并发跑（4×2.6GB LaMa + PP）会 OOM，所以
   `batch_pipeline` 还没接 `--tiers`；要么 K≤2，要么把 PP 拆成独立的后置精修阶段。
3. **预算控制**：目前只有单镜头 `pp_max_frames: 900`。整支片的 PP 帧数占比没有上限，
   一条哭戏连篇的片子可能 40% 帧都要 PP。
4. **提速实验**：`pp_scale: 0.75`（降分辨率换速度）还没测；`pp_chunk` 与显存/速度的
   曲线也只有一个点。
